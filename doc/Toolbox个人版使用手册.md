# Toolbox 个人版使用手册

更新日期：2026-10-22。适用：Go + Wails 本地桌面版；本次源码与0.1.11构建新增会话恢复、TAR安装和浏览器授权；旧版本需更新后才有对应入口，具体以实际安装包和下载页版本为准。

本手册面向个人在自己的电脑上管理 MCP。企业部署、用户和角色管理请阅读[企业 Web 版使用手册](Toolbox企业Web版使用手册.md)。

## 1. 使用边界与菜单

个人版免登录，默认拥有本机全部管理与 MCP 使用权限，不提供用户管理、角色分配和退出登录。数据、密钥和 MCP 进程位于当前电脑，独立于企业服务；下载后不依赖企业服务运行。

| 菜单 | 用途 |
| --- | --- |
| MCP 管理 | 添加、扫描、复制、配置和运行 MCP |
| 客户端 | 一键接入 Codex / Qoder、查看及删除接入记录 |
| MCP市场 | 搜索 Server，在线或离线安装 |
| Gateway | 查看接入地址、签发和撤销 Token |
| 安全策略 | 全局客户端来源 IP 规则 |
| 调用日志 / 系统日志 | 查看实际调用与应用异常 |
| 系统设置 | 开机启动、端口、运行环境、扫描目录、备份等 |

“免登录”针对桌面应用；外部客户端连接 Gateway 仍需 Token。直接在浏览器打开本机管理接口不等同于桌面免登录入口。远程 HTTP MCP、在线安装及工具外部访问仍需要网络。

## 2. 下载、安装、启动与退出

### 2.1 获取安装包

在企业网站登录页或顶部点击“下载桌面版”，按操作系统与架构选择安装包，可展开校验信息核对 SHA256。下载页只显示已发布且可用的包。

| 系统 | 使用方式 | 当前边界 |
| --- | --- | --- |
| macOS Apple Silicon / ARM64 | 解压并打开 Toolbox.app | 临时签名，未完成 Developer ID 签名及公证 |
| Windows 11及以上 x64 | 解压到固定目录，打开 Toolbox.exe；需 Edge WebView2 Runtime | 包已生成，未做 Authenticode 签名，尚未完成Windows真机验收 |
| Linux桌面版 | 当前未交付 | Linux AMD64服务端属于企业Web版 |

首次启动自动生成本机数据目录和缺失密钥，无需设置 MASTER_KEY、SETUP_KEY 或创建账号。加载期间展示骨架屏，真正失败时显示诊断和重试入口。数据库不能和企业 Web 版共用。

### 2.2 端口与运行环境

默认 Gateway 端口8090，被占用时自动选择空闲端口并保存。客户端应使用“Gateway”页实际地址，而不是始终写死8090。个人 Gateway 仅监听回环地址，不能供另一台电脑直接访问。

stdio 默认开启，Node.js、Python 等依赖不随安装包提供。在“系统设置 → 本机运行环境”检查 Server 所需环境。命令与 MCP 程序以当前系统账户权限运行，应选择信任的程序。

### 2.3 开机启动与退出

进入“系统设置 → 开机启动”，启用“登录系统时自动启动”，下次当前用户登录系统时生效。关闭开关不退出当前程序。

- macOS：使用当前用户 LaunchAgent，自动保存稳定启动副本；关闭窗口会隐藏并继续运行，通过菜单栏或应用菜单恢复窗口，选择“退出 Toolbox”或 Cmd+Q 才停止服务。
- Windows：使用当前用户的登录启动项，引用当前 Toolbox.exe 路径；请保留固定程序目录，移动后重新关闭、开启启动设置。Windows行为仍待实机验收。

退出或停止 MCP 会中断客户端连接。不要依靠关闭 macOS 窗口停止工具。

## 3. 首次使用流程

1. 启动应用，在系统设置确认 Node.js / Python 等运行环境。
2. 添加 MCP，或扫描已有配置后批量纳管。
3. 等待连接，打开“工具”确认实际工具列表。
4. 在“客户端”一键接入，或在“Gateway”签发 Token 手动配置。
5. 在客户端执行实际业务调用，在“调用日志”核对实例、工具和结果。

## 4. 配置位置说明

下文“后端所在电脑”均指当前运行个人版的电脑。扫描、安装、stdio、动态请求头助手和脚本都在本机执行，与客户端是 Codex 还是 Qoder 无关。参数与环境变量遵循各 Server 文档，没有适用于所有 MCP 的数据库表单。

## 5. MCP 管理

### 5.1 添加 HTTP MCP

进入“MCP 管理 → 添加 MCP”，选择“远程 Streamable HTTP”：

1. 填写实例名称，按需填写描述和标签。
2. 填写服务提供方给出的完整 Server URL。
3. 需要认证时点击“添加请求头”，逐项填写名称和值。
4. 可先点击“测试连接”，确认后点击“保存配置”。

Bearer 认证通常填写：请求头名称 `Authorization`，值为 `Bearer ` 加实际 Token，注意中间空格。无需认证时不添加请求头。已有请求头可直接编辑，删除行并保存即移除。

“标签”仅用于标记服务用途或环境，不授予账号权限。

#### 自动更新请求头

仅当服务口令会过期，且需要通过本机脚本获取时，展开“高级配置：自动更新请求头（可选）”。填写命令后，Toolbox 在每次 HTTP 请求前执行命令，读取其输出的 JSON 请求头，例如：

```json
{
  "X-Tencent-Meeting-Token": "替换为脚本获取的实际口令"
}
```

同名动态请求头会覆盖固定请求头。命令在 Toolbox 后端所在电脑执行，需要启用本机命令运行，且脚本和依赖实际存在。普通固定 Token 服务只需配置请求头；不需要填写动态命令。清空命令后保存可关闭此功能。

### 5.2 添加 stdio MCP

选择“本地 stdio”，按 Server 自身文档填写：

| 字段 | 填写方式 |
| --- | --- |
| 启动命令 | `node`、`python3`、`npx`、`uvx` 或实际可执行文件路径 |
| 参数 | 点击“添加参数”，每行是一个完整参数，按顺序传入 |
| 工作目录 | Server 需要的实际工作目录，可按需填写 |
| 环境变量 | 点击“添加环境变量”，逐项填写键和值 |
| 最大并发、调用超时 | 根据服务能力调整；并发参数不保证下游内部并行执行 |

启动命令与参数分开填写，不要把整条终端命令都填进“启动命令”。参数中的空格保留在同一个参数内，无需额外添加 shell 引号。

stdio 程序在后端所在电脑执行，不是在访问网页的浏览器电脑执行。企业版与个人版的 stdio 均默认开启；明确手动关闭过的设置会保留。可到“系统设置 → 本机运行环境”确认依赖与开关状态。此开关控制本机命令执行，与客户端来源 IP 规则是不同功能。

### 5.3 JSON 配置

添加或编辑实例时，切换到“JSON 配置”。支持单个服务对象，或仅包含一个服务的 `mcpServers` 对象。

HTTP 格式示例：

```json
{
  "mcpServers": {
    "team-service": {
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer 替换为实际令牌"
      }
    }
  }
}
```

stdio 格式示例：

```json
{
  "mcpServers": {
    "local-service": {
      "command": "node",
      "args": ["/absolute/path/to/server.js"],
      "env": {}
    }
  }
}
```

示例中的地址、路径和令牌必须替换为实际配置；启动参数及环境变量由各个 Server 定义。平台不能自动推断所有 MCP 的业务配置字段。

编辑已有配置时，省略 `env` 或 `headers` 表示沿用，空对象 `{}` 表示清除。编辑界面与 JSON 可能包含实际凭据，分享前应脱敏。需要导入多个服务时，使用“扫描导入”。

### 5.4 扫描导入与批量纳管

1. 进入“MCP 管理 → 扫描导入”。
2. 核对已知配置来源及读取状态，包括 Codex、Claude Code、Cursor、Toolport、Qoder。
3. 点击“扫描本机配置”。默认包含当前服务账户用户目录下的 `.qoder-cn`。
4. 查看扫描结果；可纳管且尚未纳管的配置默认全选。
5. 取消不需要的项目，点击“批量纳管”，核对提示后确认。
6. 对“需要补充配置”的项目点击“查看配置”，补齐信息后再纳管。
7. 返回实例列表查看连接结果，失败时根据诊断修复并重试。

扫描只读取配置，不执行命令；确认纳管后才会加密保存并自动启动。扫描不会修改原客户端配置文件。需要长期扫描自定义目录，在“系统设置 → 扫描目录”添加；临时扫描可展开“添加配置文件或目录（可选）”，每行填写一个绝对路径。

目录和文件须能被服务运行账户读取。Web 服务部署在服务器时，填写自己电脑的路径不会让服务器自动读取到这些文件。

### 5.5 PostgreSQL 与多个数据库

不同数据库 MCP 的连接配置不同，先确认使用的 Server 接受启动参数、环境变量还是运行时连接工具。

对于平台可识别的 PostgreSQL URI 配置，可展开数据库辅助配置，修改主机、端口、数据库名、用户名、密码处理方式与 SSL。通用方式是编辑启动参数或 JSON 中的连接配置。典型 URI 结构为：

```text
postgresql://USER:PASSWORD@DB_HOST:5432/DB_NAME
```

`DB_NAME` 是连接的数据库名；账号或密码含特殊字符时须按 URI 规则编码。不要假设填写一个名为 `DATABASE_URL` 的变量就会被所有 Server 读取。

当前参考 PostgreSQL Server 的单个进程使用一个数据库 URI。需要多个库时，可使用“增加数据库连接”复用程序配置，建立多个独立 MCP 实例与进程。此功能不等于让任意单个 MCP 进程支持多数据库。

### 5.6 启动、停止与配置生效

新增、纳管或安装后，平台会自动尝试启动并发现工具。实例行可进行“启动”“停止”，以及“更多 → 重启 / 移除实例”。移除实例会影响该服务接入，不是卸载外部客户端软件。

编辑后核对“工具”抽屉中的“已保存版本”和“运行版本”。如两者不一致，按页面提示启动或重启；不能仅凭保存成功认定运行中的连接已经切换。数据库辅助连接修改可能先验证新配置，失败时保留原运行连接，应结合错误和版本判断。

### 5.7 复制连接与标签

在实例“更多 → 复制并新建”中复用启动命令、参数、环境变量或 HTTP 请求头。程序生成不重名的实例名，保存前可修改；保存后独立启动。企业版的角色授权不会随实例复制。

每个实例当前支持一个标签。可选择其他实例已使用的标签，或输入新标签确认创建。标签在服务名称下展示，可用于筛选；标签不承担权限控制。

### 5.8 状态与自动健康检查

列表只展示“进程状态”和“MCP 测试”，已移除“工具测试”。HTTP 显示远程服务，本地 stdio 显示进程状态；悬停状态可查看 PID、检测时间、工具数或错误说明。

后台默认每30秒检查 MCP 连接，可在系统设置中开关，或调整为10–3600秒。故障实例恢复后自动更新；手动停止、隔离及调用结果未知的实例不自动重放业务请求。参考 PostgreSQL Server 另有内部只读连接校验。

实例页可见时每5秒读取最新状态，编辑期间暂停。“刷新”只读取服务器状态，不会调用所有业务工具。MCP 测试通过不代表每个业务工具均可用；需在客户端执行一次符合实际用途的调用，再核对调用日志。

上游断开、健康检查重连或实例重启后，已有 Gateway 会话在下一次请求时更新服务连接和工具目录，不再永久引用旧连接。恢复前未发送的调用会明确报错；已提交但结果未知的业务调用不会自动重放。整个 Toolbox 进程重启会结束 Gateway 会话，客户端仍需重新建立连接。


### 5.9 浏览器授权（标准 MCP OAuth）

HTTP 服务需要登录授权时，使用实例的“浏览器授权”入口，不必把网页登录密码填成请求头。该功能要求服务公开标准 MCP OAuth 元数据，并支持公开客户端的 Authorization Code + PKCE S256；仅有普通网页登录页面，不代表支持此流程。

1. 保存 HTTP MCP 实例，在需要授权的提示或“更多 → 浏览器授权”中打开授权面板。
2. 点击“准备浏览器授权”。默认尝试动态注册；服务不支持时，先在服务方注册公开客户端，将回调地址与面板显示值保持一致，再填写 Client ID。
3. 核对认证服务和回调地址，点击“前往授权”，由本人在第三方页面登录并确认权限。
4. 回调显示凭据已保存后，返回 Toolbox 刷新授权状态，点击“连接服务”。还需验证工具列表及实际业务调用，不能只以授权成功判断服务可用。
5. 服务提供刷新令牌时程序按需刷新；过期且无法刷新时重新授权。可取消待完成流程或清除本地授权，第三方平台的授权撤销仍需到其平台处理。

Token 和刷新令牌加密保存，不在列表展示。认证元数据与端点当前要求公开 HTTPS 地址；个人版使用本机 loopback 回调，企业远程部署需使用用户浏览器可访问的 HTTPS 公开地址。授权状态一次有效，超时、重启或实例地址变化后应重新发起。

授权作用于该 MCP 实例的第三方服务账号，企业成员仍以 Gateway Token 和角色识别。不同第三方账号建议建立不同实例。自定义 Authorization 请求头和 OAuth 不应同时配置。

没有标准 OAuth 元数据的服务会提示改用其要求的固定请求头或动态口令。腾讯会议不同 MCP/CLI 入口的认证方式可能不同，应按所用入口文档配置；不能将所有腾讯会议服务都视为统一 OAuth。参考[腾讯会议 MCP 官方说明](https://cloud.tencent.com/document/product/1095/133826)与[MCP 授权规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。

## 6. MCP市场

### 6.1 查询与在线安装

1. 进入“MCP市场”，输入 Server 名称或英文名称子串，点击“查询”。
2. 点击结果查看版本、来源、本地包、远程地址和配置要求。
3. 有更多结果时点击“加载更多 / 重试失败来源”。
4. 对支持的 npm / PyPI 包点击“安装此版本”。
5. 填写实例名、固定版本、必要参数和环境变量，多入口时选择正确入口。
6. 点击“安装并启动”，查看任务结果及实例入口。

搜索按 Server 名称进行，不会检索服务内部的 `query` 等工具名称。目录收录情况取决于配置的仓库，某个仓库失败会单独提示。远程 HTTP MCP 可直接在“MCP 管理”添加，无需下载安装包。

在线安装需要主机具备对应运行环境与网络。PyPI 安装支持可用 wheel，不保证任意源码项目均能安装；不要把“安装成功”视为业务调用验收完成。

### 6.2 离线安装

进入“MCP市场 → 安装离线 MCP”：

1. 选择 ZIP、TAR、TAR.GZ 或 TGZ 安装包，最大 128 MB。
2. 填写实例名，选择 Node.js、Python 3 或原生可执行程序。
3. 填写相对于包根目录的入口，例如 `dist/index.js`。
4. 填写 Server 所需参数和环境变量，点击“安装并启动”。

离线包必须包含完整依赖；安装时不会联网补齐依赖。Node.js 包需包含所需 `node_modules`，Python 包需包含所需模块，原生程序须匹配后端的系统与架构。TAR/TAR.GZ与ZIP使用相同的512 MB展开上限和10000文件上限，不支持符号链接、硬链接或特殊文件；Windows/Linux原生程序须匹配目标架构。失败时查看任务阶段及实例诊断，修复后再连接。

## 7. Gateway 与客户端接入

### 7.1 一键接入 Codex、Qoder、Qoder CN

1. 打开“客户端”，展开默认折叠的“客户端一键接入”。
2. 点击唯一的“接入客户端”按钮，在弹窗中选择客户端类型和配置版本。
3. 确认配置根目录、MCP 配置名称和 Token 有效期，点击“预览配置”。
4. 核对实际文件、现有 MCP 名称和配置片段。同名默认不覆盖；可改名或明确选择替换。
5. 点击“备份并写入”（新文件为“确认并写入”），程序签发独立 Token，备份并原子写入，保留其他 MCP 与客户端设置。
6. 在客户端重载 MCP 或重启客户端，刷新工具列表并执行一次实际调用。

| 客户端类型 | 默认配置文件 |
| --- | --- |
| Codex | `~/.codex/config.toml` |
| Qoder 桌面 / CLI | `~/.qoder/settings.json` |
| Qoder CN 桌面 / CLI | `~/.qoder-cn/settings.json` |
| Qoder CN IDE | 在配置版本中选择 `shared_client/mcp.json` 或旧版 `mcp.json`，均相对所选根目录 |

表中的 `~` 指当前电脑用户目录；桌面版可使用系统目录选择器。客户端可能有多个配置版本，以预览显示的实际文件为准。写入不会关闭客户端自身的工具调用确认。

“已写入，待客户端加载”只表示配置保存成功；“客户端已访问”表示收到真实 Gateway 请求，不等于持续在线。接入失败可“重试接入”，复用原 Token，不重复签发。

“撤销接入”会撤销 Token 并移除本次写入项；若替换过同名项，则恢复原项。其他配置保留；若该项后来被手工修改，程序会拒绝覆盖，应先撤销 Token，再核对文件手动处理。配置备份位置可在页面查看。

### 7.2 手动签发 Token 与配置客户端

在“Gateway → 签发 Token”填写客户端名称和有效期。默认30天，可选1–365天或“永久有效”。永久有效只代表不自动到期，仍可撤销；已有 Token 有效期不会自动改变。

Token 明文只在签发时显示一次，立即复制并妥善保存；遗失后撤销旧 Token 再签发。建议每个客户端使用独立 Token。

复制 Gateway 页当前接入地址，在支持 Streamable HTTP 的客户端填写 URL，并添加请求头：

```text
Authorization: Bearer <TOKEN>
```

也可复制接入模板，将 `<TOKEN>` 替换为真实值。不要公开分享带有真实 Token 的配置。连接后刷新工具列表，再实际调用。

### 7.3 删除客户端

“客户端”列表展示接入记录、Token 状态、有效期和最近访问。最近访问不是在线状态。“删除”撤销对应 Token、关闭相关 Gateway 会话并隐藏接入记录，保留历史调用日志；不会卸载客户端，也不会移除手工写入的客户端配置。一键写入的配置需还原时，使用上方对应记录的“撤销接入”。

个人版不选择 Token 所属用户，新 Token 默认可访问本机全部 MCP 和工具。客户端可以访问哪些目标资源仍受 MCP 自身凭据、数据库权限等约束。

## 8. 来源 IP 安全策略

进入“安全策略 → 添加 IP 规则”，填写客户端来源 IP 或 CIDR，选择允许或禁止。规则全局作用于全部 Gateway 客户端，不针对某个本地 MCP 程序，也不绑定单个 Token。

- 没有允许规则时，有效 Token 通过其他权限校验即可接入。
- 有允许规则时，仅匹配允许网段的来源可接入。
- 禁止规则优先于允许规则。
- 依据实际 TCP 来源 IP，不信任客户端自填的 `X-Forwarded-For`。

个人版没有用户角色授权，但来源 IP 与 Gateway Token 校验仍生效；该策略不用于授权本机 stdio 程序。

## 9. 日志与问题定位

### 9.1 调用日志

在“调用日志”按结果、实例、工具、客户端名称、Token ID 和时间筛选，点击详情查看请求 ID、归属、耗时和诊断。日志不保存完整调用参数及结果正文。

客户端归属以 Token 绑定记录为准，不以 MCP 初始化时自行上报的名称为准。复用其他客户端 Token 发起调用时，会记入该 Token 的客户端名称；需要区分调用者，应使用独立 Token。

“结果未知”表示不能确认业务是否完成。尤其是写操作，应先核对目标系统实际结果，避免重试导致重复执行。

### 9.2 系统日志

“系统日志”默认展示“异常日志”，包含启动、MCP 连接和运行中的警告与错误；切换“运行日志”查看启动、连接和重试等事件。可按关键词、级别和时间查询，并打开“详情”查看脱敏原因和实例信息。

默认每10秒自动刷新；查看详情或历史分页时暂停。最近7天日志在启动及每小时自动清理；运行与异常分文件，单文件8 MiB自动分片。该保留策略只适用于运行日志，不代表调用审计日志仅保存7天。

服务完全启动失败、无法进入页面时，查看数据库所在目录的 `runtime-logs/`。`exception` 文件对应异常，`runtime` 对应运行日志，格式为 JSONL。敏感凭据会脱敏，反馈问题前仍应检查截图及文件内容。

个人版日志直接可见。macOS 完全无法启动时也可查看数据根目录下 `toolbox.log`。本地网络权限由系统控制，修改授权后应重新连接并执行真实调用。

## 10. 系统设置

| 设置 | 操作 |
| --- | --- |
| 运行环境 | 查看 SQLite、Schema 和实例统计 |
| 服务端口 | 在可编辑时填写1024–65535的可用端口，保存并确认；客户端同步修改接入地址 |
| 扫描目录 | 添加或移除长期扫描目录；目录应实际存在且运行账户可读取 |
| 目录仓库 | 最多8个兼容官方 MCP Registry v0.1 API 的 HTTPS 根地址，保存后检测；GitHub项目页及npm镜像不是此类API |
| 自动健康检查 | 默认开启、30秒间隔，可改10–3600秒；故障连接恢复后自动更新 |
| 本机运行环境 | 检测 node、npx、Python、uv、uvx；stdio默认开启，主动关闭过的设置保留 |
| SQLite备份 / 恢复数据库 | 见备份迁移章节；关闭stdio前先停止所有stdio实例 |

## 11. 数据备份、迁移与升级

### 11.1 默认数据位置

| 内容 | macOS | Windows |
| --- | --- | --- |
| 数据根目录 | `~/Library/Application Support/Toolbox Desktop/` | `%APPDATA%\Toolbox Desktop\` |
| 数据库 | 根目录的 `data/toolbox.sqlite` | 根目录的 `data\toolbox.sqlite` |
| 密钥 | 根目录的 `local.env` | 根目录的 `local.env` |
| 安装制品 | 根目录的 `data/artifacts/` | 根目录的 `data\artifacts\` |
| 系统运行日志 | 根目录的 `data/runtime-logs/` | 根目录的 `data\runtime-logs\` |

通过 `--data-dir` 指定独立目录时，以指定目录为准。不要删除原密钥；替换程序不会自动清除数据目录。

### 11.2 备份与恢复

1. 在“系统设置 → SQLite 备份”下载一致性快照。
2. 另行安全备份对应的 `local.env` 或外部 `MASTER_KEY`；不要分享密钥。
3. 同时保存安装制品目录；数据库快照不包含安装包、外部脚本和目标数据库内容。
4. 迁移时保留原主密钥，核对系统架构、命令路径、工作目录和 Node.js / Python 等依赖。
5. 在“恢复数据库”选择备份并校验，确认恢复后重新连接客户端，做一次真实调用。

恢复会中断现有 MCP 连接，旧库保留用于回退。只复制运行中的 `.sqlite` 主文件可能遗漏 WAL 数据，请使用页面一致性备份或停服后完整迁移。只有数据库而丢失原主密钥，将无法解密原 MCP 凭据。SQLite 本身无独立服务登录密码。

### 11.3 更新桌面程序

当前采用手动升级，没有应用内自动更新：下载对应系统新包 → 备份数据及密钥 → 正常退出旧应用 → 替换程序 → 使用原数据目录启动 → 核对配置和真实调用。macOS 启动副本会随已启用的启动设置更新；Windows应保留可执行文件路径，改变路径后重新设置登录启动项。

## 12. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 扫描结果为0 | 确认运行电脑、服务账户、配置文件及读取权限，在系统设置添加正确扫描目录 |
| HTTP正常，stdio失败 | 检查本机 stdio 开关、运行环境、命令绝对路径、参数和操作系统架构 |
| 能列出 query 但执行失败 | 检查数据库地址、端口、库名、凭据和权限；发现工具不代表数据库业务可用 |
| MCP测试通过但业务失败 | 通过客户端执行对应业务调用，结合调用日志及系统异常日志排查 |
| 手动刷新后状态未变 | 刷新只读状态；检查是否手动停止、隔离、配置未运行或尚在健康检查间隔中 |
| 市场搜不到服务 | 按 Server 名称搜索，加载更多并检查来源；不会搜索服务内的工具名称 |
| 安装完成但不能连接 | 核对包入口、依赖、参数、环境变量；安装成功不等于业务可用 |
| 配置修改未生效 | 比较已保存版本与运行版本，按提示启动或重启，不要仅凭保存成功判断 |
| 客户端缺少工具或拒绝调用 | 检查实例状态、Token有效期和来源IP策略；重载客户端并核对日志 |
| 修改端口后客户端断开 | 复制 Gateway 页面新地址，更新配置并重新连接 |
| 数据库被占用 | 正常退出使用同一数据目录的旧进程，不要启动两个进程共用 SQLite |
| 恢复密钥不匹配 | 使用备份对应的原主密钥，勿删除密钥尝试重置 |
| macOS本地网络列表存在两个Toolbox | 这是授权记录而非运行进程列表；临时签名的不同构建可能产生同名记录，需区分应用实际路径和版本 |
| macOS关窗口后仍可调用 | 窗口隐藏属于后台运行，使用“退出 Toolbox”停止 |
| 访问企业网站看不到本机配置 | 企业服务器和个人应用使用独立数据，未提供自动同步 |
